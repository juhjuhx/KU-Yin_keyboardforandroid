# 現有實機驗收能力深讀

## 產品路徑

`KuYinInputMethodService.onCreate` 透過 NativeStartupGate／NativeChewingEngineOwner 啟動 JNI，ProductionDecoderResolver 決定 native session 或 startup fallback。`onStartInput` 正規化 EditorPolicy／EditorEnterPolicy、learning 與 preferred/effective mode。Compose 的 Enter 保留 session.dispatch → orderedCommits → 僅 unconsumed 才呼叫 service 的 normalized editor behavior。

P1-B mapping source 是 `KeyboardLayout.Dachen` → DachenKeyboardRows；不是另造 26 鍵注音映射。本階段不改 geometry。

`waitForImeVisible` 的名稱也不是跨 API 的完整可見性證據：API ≥30 使用 WindowInsets.Type.ime 的 isVisible；API 24–29 使用 InputMethodManager.isAcceptingText，只代表 served view 接受 full text edits，不等於 IME window visible。官方語義：[InputMethodManager.isAcceptingText](https://developer.android.com/reference/android/view/inputmethod/InputMethodManager#isAcceptingText())。

以上是逐源碼判讀的 coverage 邊界，不是 runtime 失敗裁定。既有測試原樣保留，不改 assertion 讓它看起來更完整。

## 既有 debug host

`app/src/debug/.../ImeHostActivity.kt` 只有一個 multiline EditText，設定 `TYPE_CLASS_TEXT | TYPE_TEXT_FLAG_MULTI_LINE`、IME_ACTION_DONE、minLines=3；沒有 custom action、NUMBER／PHONE／DATETIME／TYPE_NULL 切換、EditorInfo 視覺顯示或 editor action counter。

TextView 可能在 onCreateInputConnection 再正規化 multiline flags；Activity 中的 imeOptions 設值不等於送達 IME 的完整 EditorInfo。驗收時應在受控 host boundary 確認 metadata，不能由畫面長相推定 flags。

Debug manifest 的 host `exported=false`，既有 ActivityScenario 可以啟動；不能把 `adb shell am start` 當作可由 shell 直接開啟此 host 的既定可用方法。

## 既有 runtime_smoke.sh

會 bootstrap、installDebug、以未指定 serial 的 adb 找 IME／enable／set，再 connectedDebugAndroidTest。適合既有專用 emulator CI，但不作本輪實機入口：它重建／安裝 app、沒有保留與還原原 default IME，多裝置時未 pin serial；本輪改用已封存 artifact 的明示 serial 操作手冊。原 script 不修改。

## 結論與下一個最小切片

先準備同一 Debug APK＋既有 instrumentation APK，可立即執行已存在的 5 測。一旦有裝置先做此基礎 smoke，仍須另外完成受控 editor matrix；只有合適 metadata host、action counter 和真 IME UI 操作，才可宣稱 P1-C/D physical coverage。

完整 matrix 需要下一步 debug-only fixture／test coverage：固定 editor configs、記錄當次 EditorInfo、action callback ID/count 與固定測試文字的 newline delta；不能讓 production UI 或 libchewing 擔任 editor metadata 決策。此為未實作的精確工作項，不以文檔計畫當作程式完成。

本輪使用者要求接續驗收，既有產品契約已核定；沒有新功能或產品架構實作，故不新增設計審批。若進入新增 fixture 切片，先呈現此深讀與 bounded 規格，再實作。
