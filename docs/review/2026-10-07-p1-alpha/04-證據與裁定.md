## Coverage 缺口

現有 instrumentation 4 類／5 方法僅提供 direct native／IME bind-recreate／identity smoke。其中 API 24–29 的 recreate gate 只查 isAcceptingText，不等於 window visibility；API ≥30 才有 WindowInsets visibility assertion。完整矩陣 30 cases 初始全部 NOT_TESTED。P1-C 的精確 editor／learning 邊界、P1-D action count／ID／newline delta、真 Compose candidate selection 和實體 rotation，仍需受控 host／native policy observer 或可直接證明同等 metadata 的 test surface。

連續句 test 輸入兩音節，但 assertions 只要求非空 preedit、至少一個 CJK、非空 candidates／final commit；不能由此嚴格推定兩音節都完整 coexist。B03 仍是另需真裝置證據的完整期望。

P1-A forced-startup fallback 的 physical fault fixture 也未建立；不能用破壞已封存 APK／user dictionary 的方式偽造通過。現有 narrow JVM failure tests 為既有證據，不能替代 device 分層。

## 文檔糾錯

- CURRENT_STATE 原「兩個 instrumentation tests」更正為四類／五方法，區分 compile/package 與 runtime。
- CURRENT_STATE 明示 historical C4 CI 不代表 local Alpha CI；本輪未 push。
- SECURITY_AUDIT 原「zero uses-permission」限定為來源 manifest；merged APK 有 AndroidX Core 1.18.0 引入的 app-defined signature permission，未增加 INTERNET／VIBRATE。這是 artifact 描述更正，非產品權限變更或全量安全認證。
- 所有 runtime 契約／缺口詳 01、02；deep-read 不把既有 method name 的 once／commit 字樣當作實際 assertions。

## 限制

無裝置時不安裝／改變 IME 選擇、不跑 connected tests；測試 APK 準備完成不代表 device PASS。P1-D 最後 OCR provider health 為 401；本輪未重新執行 provider 掃描，不聲稱當前 OCR service 狀態或掃描通過。

Release 的既有 keystore 缺口不變；本輪只驗證 Debug certificate。M4、remote push、release signing 皆未開始。LSP tool/CLI 本環境不可用；本輪無 Kotlin 原始碼修改，已執行既有 Kotlin instrumentation 編譯／packaging 與文件 static checks。
