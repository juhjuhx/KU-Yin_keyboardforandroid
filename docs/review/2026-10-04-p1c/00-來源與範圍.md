# P1-C 非文字 editor composition 政策

## 根因

1. `EditorPolicy.from` 已對 NUMBER／PHONE／DATETIME／TYPE_NULL 設定 `allowComposition=false` 與 `allowCandidates=false`。
2. `EffectiveModePolicy` 卻只判斷 `isSensitive || forceAscii`。非文字、非密碼欄位會要求套用使用者偏好的 ZHUYIN。
3. `KuYinEngine.setMode(ZHUYIN)` 遇到禁止 composition 的政策時直接 return；若先前模式是 ZHUYIN，原模式沒有被清掉。
4. Compose 注音按鍵直接 dispatch 至 native `ChewingEngineSession`，不經 fallback engine 的 `onZhuyinKey` 防線，因而仍可能送出原生組字按鍵。
5. `allowPersonalizedLearning` 原本只排除密碼與 NO_PERSONALIZED_LEARNING，普通非文字欄位仍會使 native learning 開啟。

## 修正契約

- `EffectiveModePolicy` 以 `!allowComposition` 強制暫時使用現有 ENGLISH 畫面。
- `EditorPolicy` 只有 `supportsChewing && !noPersonalizedLearning` 才允許個人化學習；非文字欄位、密碼及 FORCE_ASCII 都停用。
- service 既有 `session.Reset` 清掉跨欄位 preedit／candidates，沒有修改 reset 或 lifecycle 時序。
- 自動模式覆蓋不改寫 `userPreferredMode`；返回一般文字欄位恢復原偏好。
- 限兩個產品檔：`EditorPolicy.kt`、`EffectiveModePolicy.kt`。service、UI、native decoder 與 Enter 政策不修改。

## 驗證矩陣

非文字：TYPE_NULL、NUMBER、SIGNED NUMBER、DECIMAL NUMBER、SIGNED+DECIMAL NUMBER、PHONE、DATETIME、DATE、TIME。驗證 composition／candidate／learning 禁止，原 action normalization 與 isSensitive／forceAscii 欄位語義維持正確。

一般文字：NORMAL、URI、EMAIL_ADDRESS、WEB_EDIT_TEXT 保持 composition／candidates／learning 可用。既有密碼、FORCE_ASCII、NO_PERSONALIZED_LEARNING 測試繼續驗證。

新 `NonTextEditorServiceTest` 使用真實 `KuYinInputMethodService.onStartInput`、`KuYinEngine`、`ChewingEngineSession` 與 Compose `KuYinKeyboardUi`；在測試欄位注入 recording native seam，不執行 `onCreate`／詞庫安裝／JNI。涵蓋跨欄位 reset、learning 變化、全部偏好模式的恢復、restarting，以及非文字欄位切回注音被拒絕。

現有 ENGLISH 畫面沒有獨立數字列，數字入口是 `?123` 符號頁。UI 測試先驗證不出現注音，再從既有符號頁點 `1`，確認直接提交 ASCII、native 未收到注音鍵。初版測試誤以為 ENGLISH 有 `1`；此假設已修正，且用原政策重新跑出最終 RED 後再驗證 GREEN。

## 官方來源與界限

- [Android InputType](https://developer.android.com/reference/android/text/InputType#TYPE_MASK_CLASS)：以 class／variation mask 解讀 editor。
- [TYPE_NULL](https://developer.android.com/reference/android/text/InputType#TYPE_NULL)：不是 rich input connection，不能視為普通文字組字欄位。本切片禁止中文 composition；沒有新增完整 raw key-event 輸出模式，因此不宣稱 TYPE_NULL 全功能相容。
- [InputMethodService.onStartInput](https://developer.android.com/reference/android/inputmethodservice/InputMethodService#onStartInput(android.view.inputmethod.EditorInfo,%20boolean))：依新 editor 初始化狀態；本次 callback 測試只提供 JVM 證據。

數字 keypad 專用設計、TYPE_NULL raw key-event dispatch、缺失 EditorInfo 的 fallback、未知 input class 相容政策、Enter／IME_FLAG_NO_ENTER_ACTION 與 M4 不在本次產品修改範圍內。nullable EditorInfo 的既有 fallback 沒有更改。
